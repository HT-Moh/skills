# engineering/ — codebase audit, hygiene and ways-of-work tools

| Skill | What it does |
|-------|--------------|
| [**breakdown-epic-arch**](./breakdown-epic-arch/SKILL.md) | User-invoked. Turns an Epic PRD into a technical architecture specification at `docs/ways-of-work/plan/<epic>/arch.md` with a component diagram, stack decisions and a t-shirt size. Vendored from github/awesome-copilot (MIT). |
| [**breakdown-epic-pm**](./breakdown-epic-pm/SKILL.md) | User-invoked. Turns an epic idea into an Epic PRD at `docs/ways-of-work/plan/<epic>/epic.md`: problem, goals, personas, features and enablers, success metrics. First step of the planning chain. Vendored from github/awesome-copilot (MIT). |
| [**breakdown-feature-implementation**](./breakdown-feature-implementation/SKILL.md) | User-invoked. Turns a feature PRD into an implementation plan at `docs/ways-of-work/plan/<epic>/<feature>/implementation-plan.md`: architecture, data model, API, frontend, security and performance. Vendored from github/awesome-copilot (MIT). |
| [**breakdown-feature-prd**](./breakdown-feature-prd/SKILL.md) | User-invoked. Turns one feature or enabler from an epic into a feature PRD at `docs/ways-of-work/plan/<epic>/<feature>/prd.md` with user stories and acceptance criteria. Vendored from github/awesome-copilot (MIT). |
| [**breakdown-plan**](./breakdown-plan/SKILL.md) | User-invoked. Turns the feature artifacts into a GitHub project plan and an issues checklist with the Epic > Feature > Story/Enabler > Test hierarchy, dependencies, labels, estimates and project automation; issues are created with `gh`. Vendored from github/awesome-copilot (MIT). |
| [**breakdown-test**](./breakdown-test/SKILL.md) | User-invoked. Turns the feature artifacts into a test strategy, a test issues checklist and a QA plan under `docs/ways-of-work/plan/<epic>/<feature>/`. Vendored from github/awesome-copilot (MIT). |
| [**bug-receipt**](./bug-receipt/SKILL.md) | User-invoked. Closes a defect or incident with a BUG RECEIPT (VERIFIED, PARTIAL or BLOCKED) and an optional receipt.json validated by the shipped script, posted as the issue's closing comment. Vendored from github/awesome-copilot (MIT). |
| [**bug-reproduction-brief**](./bug-reproduction-brief/SKILL.md) | User-invoked. Turns a vague, intermittent or environment-specific bug report into a minimal, evidence-backed reproduction before any fix is proposed, posted into the bug issue. Vendored from github/awesome-copilot (MIT). |
| [**conventional-branch**](./conventional-branch/SKILL.md) | User-invoked. Names or checks a branch against the Conventional Branch spec with this repo's issue rule, `<type>/<issue>-<slug>` (feature/, bugfix/, hotfix/, release/, chore/ plus AI-agent prefixes). Vendored from github/awesome-copilot (MIT). |
| [**create-architectural-decision-record**](./create-architectural-decision-record/SKILL.md) | User-invoked. Writes an Architectural Decision Record to `docs/adr/adr-NNNN-<slug>.md` with context, alternatives, decision and consequences, linked from its issue. Vendored from github/awesome-copilot (MIT). |
| [**create-github-issue-feature-from-specification**](./create-github-issue-feature-from-specification/SKILL.md) | User-invoked. Creates one Feature issue from a specification file under `spec/`, with the body laid out like the `feature_request.yml` form and the type set afterwards. Vendored from github/awesome-copilot (MIT). |
| [**create-github-issues-feature-from-implementation-plan**](./create-github-issues-feature-from-implementation-plan/SKILL.md) | User-invoked. Creates one issue per phase of an implementation plan under `plan/` (Feature or Task), links them as sub-issues of the named epic. Vendored from github/awesome-copilot (MIT). |
| [**create-github-issues-for-unmet-specification-requirements**](./create-github-issues-for-unmet-specification-requirements/SKILL.md) | User-invoked. Compares a specification under `spec/` with the code, searches existing issues, and creates one Feature issue per requirement the code does not meet. Vendored from github/awesome-copilot (MIT). |
| [**create-implementation-plan**](./create-implementation-plan/SKILL.md) | User-invoked. Writes a phased implementation plan to `plan/<purpose>-<component>-<version>.md` for a feature, refactor, upgrade or infrastructure change; each phase is sized to become one GitHub issue. Vendored from github/awesome-copilot (MIT). |
| [**create-specification**](./create-specification/SKILL.md) | User-invoked. Writes an AI-readable requirements specification to `spec/spec-<purpose>-<topic>.md` with numbered requirements, constraints, interfaces and acceptance criteria. Vendored from github/awesome-copilot (MIT). |
| [**create-technical-spike**](./create-technical-spike/SKILL.md) | User-invoked. Writes a time-boxed technical spike document with research questions, experiments, decision criteria and a `spike`-labelled issue to close with the decision. Vendored from github/awesome-copilot (MIT). |
| [**dead-code-sweep**](./dead-code-sweep/SKILL.md) | Finds dead code, stale comments/docs, and config/env gaps — mechanical detectors (knip, vulture, ruff) accuse, a six-class reference search convicts or acquits, and every finding ships with a DELETE/REWRITE/KEEP verdict and its evidence line. |
| [**github-issues**](./github-issues/SKILL.md) | User-invoked. Creates and edits GitHub issues through `gh`: labels, assignees, milestones, issue types, sub-issues, blocked-by dependencies, project fields and searches, with GraphQL where gh has no flag. Rewritten from the upstream MCP-tool version. Vendored from github/awesome-copilot (MIT). |
| [**pr-address-feedback**](./pr-address-feedback/SKILL.md) | User-invoked. Walks PR review comments one by one through `gh`, decides per comment whether to change code or reply with reasoning, and builds an approvable resolution plan before editing anything. Vendored from github/awesome-copilot (MIT). |
| [**refactor-to-quality**](./refactor-to-quality/SKILL.md) | Drives a spaghetti/legacy codebase to high quality behind a green test suite: isolates on a branch, builds a safety net (characterization tests if none), applies named refactorings and — only where they remove real duplication — design patterns, commits small, and iterates until an explicit engineering charter (file/function length, complexity, DRY/KISS/YAGNI, layering, folders, tests) fully passes. Resists over-engineering as hard as it raises structure. |
| [**update-implementation-plan**](./update-implementation-plan/SKILL.md) | User-invoked. Updates an existing plan under `plan/` with new or changed requirements, keeping identifiers and status fields consistent. Vendored from github/awesome-copilot (MIT). |
| [**ways-of-work**](./ways-of-work/SKILL.md) | User-invoked router for the GitHub work-tracking method: maps the phase you are in (epic, feature, spec, plan, issues, branch, bug, PR, decision) to the skill to type and lists the `gh` commands for typed issues, sub-issues and project items. |
